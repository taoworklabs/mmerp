# E2E reorganisation and faster CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CI goes green in ≤ 5 minutes with the same checks, and every `web/e2e` file is named after the feature it tests.

**Architecture:** `.github/workflows/ci.yml` splits job `check` into parallel `gen`, `lint`, `test`, `e2e` jobs plus an aggregate `check` job; `image` stops waiting. In `web/e2e`, duplicated helpers move to `helpers.ts`/`api.ts` first, `personal-space` stops depending on `m6`, then each `m{n}.spec.ts` is renamed or split with test bodies moved verbatim.

**Tech Stack:** GitHub Actions, Playwright 1.63 (`@playwright/test`), TypeScript, Make.

**Spec:** `docs/superpowers/specs/2026-10-29-e2e-ci-design.md`

## Global Constraints

- Same checks as today: `make gen` with no diff, `make lint`, `make test`, `make e2e`, `make image`, `make smoke`. Nothing dropped or weakened.
- Required status checks `check` and `image` must keep existing with those exact job names. Do not edit the GitHub ruleset.
- Test bodies move verbatim; only imports, helper calls and test-data names change. No test is added, removed or rewritten.
- Files stay flat in `web/e2e/`. No new npm or Go dependencies.
- Comments never name milestones, ADRs or docs. Code and commits in English; Conventional Commits.
- Test data names drop milestone ids (`M9A…`, `m4m_`, "Công ty M4…") for ids derived from the new file name; uniqueness via `runId()` stays.
- **Never start `make e2e`, `make lint` or a Playwright test run without asking the user first.** `pnpm -C web exec playwright test --list` and `pnpm -C web typecheck` (tsc covers `web/e2e`) are allowed at any time.
- Branch `ci/faster-ci-e2e` off `main`, one commit per task, one PR at the end; ask the user before creating issues, pushing or opening the PR.

## Review Focus

1. A test lost or duplicated while splitting → the `--list` total must equal the baseline after every task (Tasks 3–7 each check it).
2. A split file missing part of the shared `beforeAll` it used (e.g. the `:8091` tests reading the `m9` employees and timesheet) → typecheck catches missing variables; the user's `make e2e` run in Task 8 catches missing data.
3. Order inside the `exclusive` project mattering → Task 2 runs each exclusive file alone after setup.
4. The aggregate `check` job passing when a needed job failed or was skipped → Task 8 makes it fail unless every needed job's result is `success`.
5. A Playwright cache hit with missing OS packages → the `e2e` job runs `playwright install-deps chromium` on a hit (or `install --with-deps` on a miss).

### Task 1: Shared helpers

**Files:**
- Modify: `web/e2e/helpers.ts`, `web/e2e/api.ts`
- Modify: every spec with a local copy (found with `grep -nE "^async function (as|signInAs|ok|status|fixture)\b|const (tenantToday|addDays|workdayAhead) =" web/e2e/*.ts`)

**Interfaces:**
- Produces (`helpers.ts`):
  - `signInAs(page: Page, login: string, url: string, pw?: string): Promise<void>`: goto, fill, submit, wait for the account button. `pw` defaults to `password` from `api.ts`.
  - `as(browser: Browser, login: string, url: string, viewport?: { width: number; height: number }): Promise<Page>`: new context (with viewport if given), then `signInAs`.
  - `status(page: Page): Locator`: whatever the copies in m3/m4/approval-actions/approval-flows do; if they differ, keep the variants under distinct names.
  - `fixture(name: string): string`: absolute path into `web/e2e/fixtures`.
- Produces (`api.ts`):
  - `ok(res: Promise<{ status(): number; text(): Promise<string> }>): Promise<void>`: as the copy in `m6.spec.ts:12`.
  - `tenantToday(): string`, `addDays(iso: string, n: number): string`, `workdayAhead(n: number): string`: as in `approval-overdue.spec.ts:15-22`.
  - `snapshotRules(api, types: string[])` / `restoreRules(api, snapshot)`: the save/restore the four approval-* files do in `beforeAll`/`afterAll`.
- Avoid a circular import: `helpers.ts` may import `password` from `api.ts`, not the other way round. If `api.ts` imports `admin` from `helpers.ts` today, move `admin` to `api.ts` and re-export it from `helpers.ts`.

- [ ] **Step 2: Add the helpers above**, then replace each local copy whose behaviour matches. A copy with different behaviour (e.g. `accounts.spec.ts:14` takes a password, `personal-space.spec.ts:59` has no login argument) either maps onto the shared signature through its optional args or stays local.
- [ ] **Step 3: Verify.** Run `pnpm -C web typecheck` (expected: no errors) and `--list` (expected: total equals the baseline).
- [ ] **Step 4: Commit** with `refactor(web): share e2e sign-in, api and date helpers`.

### Task 8: Parallel CI

**Files:**
- Modify: `.github/workflows/ci.yml`

**Interfaces:**
- Jobs: `gen`, `lint`, `test`, `e2e`, `check` (aggregate), `image`. Triggers, `concurrency` and the Postgres service definition stay as they are now.

- [ ] **Step 1: Set up the jobs.**
  - Each of `gen`, `lint`, `test` and `e2e` does checkout, setup-go (`go-version-file: go.mod`, default cache on), pnpm v11 and Node 24 with the pnpm cache on both lockfiles, as today. Then it runs its make target.
  - `gen` also runs the existing "Generated code is committed" step.
  - `test` and `e2e` get the Postgres service and `TEST_DATABASE_URL`.
  - `lint` adds an `actions/cache` for `~/.cache/golangci-lint`, keyed on `go.sum` and the golangci version in the `Makefile`.
  - `e2e` adds an `actions/cache` for `~/.cache/ms-playwright`, keyed on the `@playwright/test` version resolved in `web/pnpm-lock.yaml`. On a cache miss it runs `playwright install --with-deps chromium`; on a hit it runs `playwright install-deps chromium`. It keeps the trace upload on failure.
- [ ] **Step 2: Add the aggregate job.** `check` has `needs: [gen, lint, test, e2e]` and `if: always()`, and one step that fails unless every `needs.*.result` is `success`. For example: `run: test "${{ join(needs.*.result, ',') }}" = "success,success,success,success"`.
- [ ] **Step 3: Unblock `image`.** Remove `needs: check` from `image`.
- [ ] **Step 4: Verify locally.** Validate the YAML with `go run github.com/rhysd/actionlint/cmd/actionlint@latest .github/workflows/ci.yml`. This runs through `go run`, so nothing is added to the repo. Expected: no output.
- [ ] **Step 5: Commit** with `ci: run gen, lint, test and e2e as parallel jobs`.
- [ ] **Step 6: Final verification, after asking the user.**
  - The user runs `make e2e` locally, or approves running it. Expected: all pass, with the same total as the baseline.
  - After the user approves pushing the branch, collect the wall time of three CI runs on it with `gh run view <id> --json jobs`, from the first job start to the last job end. Push an empty commit to get a rerun with a warm cache.
  - Expected: each run takes ≤ 5:00. If `e2e` alone exceeds ~4:30, stop and report back. Sharding is the spec's fallback and needs a decision first.
