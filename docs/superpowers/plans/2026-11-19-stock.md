# Stock (M19) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Stock area of its own, plus transfer (`CK`) and stocktake (`KK`) documents over the existing `shared/stock` ledger.

**Architecture:** Both documents are `stock.` record types in `internal/shared/stock`, built exactly like `stock.adjustment` (`adjustment*.go`). The ledger gains `RecordCounts`, which turns counted quantities into deltas under the balance lock. The frontend area `web/src/stock` takes over the stock and item screens from `web/src/sales` and calls only `shared/api/core`.

**Tech Stack:** Go, Huma, sqlc, Postgres 18, River; React, TanStack Query, react-hook-form, `@mmerp/ui`; Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-19-stock-design.md` (ADR-0100).

## Global Constraints

- Quantities are `numeric(15,3)` / `decimal.Decimal`, never float; at most 3 decimals, absolute value < 10^12.
- Services query only through `store.<Query>.Run(ctx, …)` and `data.List`; writes inside `platform.InTx`.
- Lock order: document row → serials (sorted) → balances (sorted by warehouse, item, lot, serial).
- Error codes are stable snake_case with params; user text only in `vi` and `en` i18n.
- `ProductGate` never refuses `stock` (`Product: "stock", Shared: true`).
- Write needs `stock.manage` tenant-wide; read needs `stock.view`.
- Areas never import each other; the stock area uses `@/shared/api/core` only.
- Comments short, no references to docs, ADRs or milestones.
- Do not run `make lint` or `make e2e` unless the user asks; `go test` of touched packages, `pnpm -C web typecheck` and Vitest are fine.

## Review Focus

1. A stocktake line whose lot or serial does not exist yet and is counted 0: no move, book 0, no lot created. Test in Task 1.
2. A serial counted 1 in warehouse B while on hand in warehouse A: refused `stock_serial_quantity`. Test in Task 1.
3. A transfer of a lot item whose lot carries an expiry: the incoming move must not send an expiry (none is stored on transfer lines), so `stock_lot_expiry_mismatch` never fires. Test in Task 3.
4. A stocktake with the same (item, lot, serial) twice, lot codes differing only in case or spaces: refused `stock_stocktake_duplicate_line`. Test in Task 4.
5. A user holding `item.view` only (no `stock.*`) enters the Stock area and sees Items but no stock menu entries or routes. Test in Task 6 (`access` Vitest or e2e in Task 9).

- Test: `internal/shared/stock/ledger_test.go`

**Interfaces:**
- Produces:
  ```go
  // Count is what a stocktake found for one key of one warehouse; Quantity ≥ 0.
  type Count struct { LineNo int; ItemID int64; Lot *LotRef; Serial *string; Quantity decimal.Decimal }
  // CountResult is a count's on hand when it posted.
  type CountResult struct { LineNo int; Book decimal.Decimal }
  func (s *Service) RecordCounts(ctx context.Context, ref record.Ref, warehouse int64, counts []Count) ([]CountResult, error)
  ```
  Results in the order of `counts`. Moves are written with `Quantity = counted − book` for non-zero differences only; `Void` reverses them as any other moves.
